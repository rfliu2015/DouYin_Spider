## 2. 依赖安装

### 2.1 为什么不能直接 `pip install -r requirements.txt`

存在**硬冲突**：

```
ERROR: Cannot install -r requirements.txt and protobuf>=5.27
  The user requested protobuf>=5.27
  blackboxprotobuf 1.0.1 depends on protobuf==3.10.0
```

- `static/Response_pb2.py` 由 protoc 5.27.1 生成，需要 `from google.protobuf import runtime_version`
- `blackboxprotobuf` 的元数据写死 `protobuf==3.10.0`，但**该声明是过时的**

> **实测**：blackboxprotobuf 只用了 `google.protobuf.internal` 的几个编码原语，不依赖 3.10 特有行为。protobuf 5.x 与 7.x 下解码结果一致。

**反向验证**：protobuf 4.x 直接 `ImportError: cannot import name 'runtime_version'`，**不能为迁就它而降级**。

### 2.2 三步安装法

```powershell
# 第 1 步：装除 protobuf / blackboxprotobuf 外的全部依赖
Get-Content requirements.txt |
  Where-Object { $_ -notmatch '^(protobuf|blackboxprotobuf)' -and $_ -notmatch '^#' -and $_.Trim() } |
  Set-Content req_rest.txt
pip install -r req_rest.txt

# 第 2 步：protobuf 5.x（限定 <6 避免跨大版本）
pip install 'protobuf>=5.27,<6'

# 第 3 步：跳过元数据约束
pip install --no-deps blackboxprotobuf

# 清理
Remove-Item req_rest.txt
```

## 4. 共用环境升级 protobuf 的影响

本项目要求 `protobuf>=5.27`，会把共用 WinPython 的 `4.25.1` 升到 `5.29.6`。

**兼容性核查结论**（升级前已确认）：

| 包 | 要求 | 影响 |
|---|---|---|
| `streamlit` | `protobuf<7,>=3.20` | ✅ 兼容 |
| `ortools` | `protobuf>=4.25.0` | ✅ 兼容 |
| `onnx` / `onnxruntime` | `>=3.20.2` / 无限制 | ✅ 兼容 |
| `mysql-connector-python` | `>=3.0.0` | ✅ 兼容 |
| `datasets` | `<4.0.0`（**仅 extras**） | ⚠️ 主路径不受影响 |
| `modelscope` | `<3.21.0`（**仅 extras**） | ⚠️ 主路径不受影响 |

**回滚命令**：

```powershell
pip install protobuf==4.25.1
```

> 回滚后本项目将无法运行（`Response_pb2.py` 加载失败）。

## 5. 两个环境坑

### 坑 1：循环导入

```python
import builder.auth
# ImportError: cannot import name 'DouyinAuth' from partially initialized module
```

**原因**：

```
builder/auth.py:9        → from dy_apis import douyin_api
dy_apis/douyin_api.py:22 → from builder.auth import DouyinAuth
```

**规避**：任何独立脚本**必须先导入** `dy_apis.douyin_api`（或直接 `import main`）：

```python
import dy_apis.douyin_api  # 必须放第一行
from utils.common_util import load_env
a = load_env()
```

### 坑 2：Windows GBK 终端

二维码渲染会失败：

```
WARNING | print_qrcode | 终端二维码渲染失败: 'gbk' codec can't encode character '\u2580'
```

**解决**：

```powershell
$env:PYTHONIOENCODING='utf-8'
```
