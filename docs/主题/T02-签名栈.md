# 签名栈

> 定论文档。抖音 web 端 5 类风控签名的实现位置与关键参数。
> **这是本项目最有价值的部分**——全部纯 Python，无浏览器依赖。

---

## 1. 总览

| 签名 | 产物 | 实现文件 | 行数 | 依赖浏览器 |
|---|---|---|---|---|
| `a_bogus` | query 参数 `a_bogus` | `utils/ab_pure.py` | ~400 | ❌ |
| secsdk webSign | query 参数 `x-secsdk-web-signature` | `utils/secsdk_web_sign.py` | 187 | ❌ |
| `msToken` | query 参数 `msToken` | `utils/mstoken.py` | — | ❌ |
| `x-tt-session-dtrait` | 请求头 | `utils/dtrait.py` + `dtrait_features.py` | 225 | ❌ |
| `bd-ticket-guard` | 请求头（5 个） | `utils/bd_ticket.py` | ~300 | ❌ |
| `x-secsdk-csrf-token` | 请求头 | `utils/dy_util.py:207` | — | ❌ |

**与自研 dyclaw 的对比**：dyclaw 的 webSign 要启动 headless 浏览器跑 JS，且注释里自己写了「headless 模式下 secsdk 通常不加载，请用 headless=False」。本项目把算法重写成 Python，**既不需要浏览器，也不怕无头检测**。

## 2. `a_bogus`：最容易被坑的地方

### 2.1 按 host 分 4 套 profile

```python
# utils/ab_pure.py:41
HOST_APP_IDS = {
    "www.douyin.com":     (6383, 11881),
    "live.douyin.com":    (6383, 7571),
    "creator.douyin.com": (2906, 33638),
    "login.douyin.com":   (6383, 6241),
}
```

签名里**内嵌 `(aid, page_id)`**，三套值不同。

> ⚠️ **用错直接判人机验证**。dyclaw 只有 www 一套，一旦要碰 creator 域就会踩。

### 2.2 调用方式

```python
from utils.dy_util import generate_a_bogus
sig = generate_a_bogus(query, data="", host="www.douyin.com")
```

通常不直接调用，而是通过 `builder/params.py` 的 `Params.with_a_bogus()`。

## 3. secsdk webSign

### 3.1 原理

```
规范化 URL → 拼接固定盐 → MD5（32 位小写十六进制）= x-secsdk-web-signature
```

固定盐（与账号无关，已探针确认）：

```python
WEBSIGN_CONST = "A96D855A08C0A9707F8BEF0D9A527E4E"
```

### 3.2 受保护路径

```python
from utils.secsdk_web_sign import sign_url, PROTECTED_PATHS_GET

# PROTECTED_PATHS_GET: 14 条
#   /aweme/v1/web/aweme/detail/     /aweme/v1/web/aweme/post/
#   /aweme/v1/web/aweme/favorite/   /aweme/v1/web/aweme/listcollection/
#   /aweme/v1/web/mix/aweme/        /aweme/v1/web/tab/feed/
#   /aweme/v1/web/mix/list/         /aweme/v1/web/music/aweme/
#   /aweme/v1/web/music/list/       /aweme/v1/web/mix/detail/
#   /aweme/v1/web/mix/listcollection/  /aweme/v1/web/music/detail/
#   /aweme/v1/web/collects/list/    /aweme/v1/web/collects/video/list/
```

### 3.3 关键用法

```python
url = sign_url('https://www.douyin.com/aweme/v1/web/aweme/detail/?aweme_id=...',
               ts=..., uifid=...)
```

> ⚠️ **必须发送 `sign_url()` 返回的完整 URL**，不能拿原始 URL 直接发——签名里含 `timestamp`，已拼进 URL。

### 3.4 缺签名的后果

不在受保护列表里的接口，缺签名通常没事；**在列表里的**会返回：

```
HTTP 403  Blocked by ArgusSecurityPlugin Signature Not Found
```

> **手工探针必踩的坑**：自己拼 request 打 `aweme/detail` 会被 Argus 拦，但项目封装的 `get_work_info` 正常——因为后者走了 `Params` 的签名流程。

## 4. msToken

### 4.1 两个域、两种长度

| 域 | `ms_appid` | 长度 | 用途 |
|---|---|---|---|
| `www.douyin.com` | 6383 | **164** | 主站接口 |
| `creator.douyin.com` | 2906 | **184** | 发布 / 评论等 creator 域接口 |

```python
auth.msToken          # 主站，惰性获取 + TTL 自动续期
auth.creator_msToken  # creator 域
```

### 4.2 特性

- **绑定 `ttwid`**：换设备必须重新换 token
- **TTL 自动续期**：`builder/auth.py:1310` 的 property，过期自动重取
- 续期时把旧 token 挂 query 上（实录 `reqid=408/920/937` 都这么发）

## 5. `x-tt-session-dtrait`

### 5.1 结构

```
d0_<RSA加密>_<AES-CBC加密>
```

外层 JSON payload：

```json
{"dtrait":"<设备特征blob>","timestamp":<秒>,"sdkVersion":"1.0.31-beta.4","path":"<pathname>"}
```

**关键**：`path` 参与加密，所以**每个接口的头都不一样**，不能复用。

### 5.2 内层 blob 的头字节位域

```python
# utils/dtrait_features.py
head = ((reserved & 0x3) << 6) | ((dtrait_type & 0x1) << 5) \
     | ((access_type & 0x1) << 4) | (version & 0xF)
# 默认参数 = (0<<6) | (1<<5) | (0<<4) | 0 = 0x20 = 32
```

这个位域是**本项目解出来的**，外部文章只观察到「prepend 是这几个数」。

### 5.3 生成

```python
dt = auth.session_dtrait_header(api_path)   # api_path 必须是纯 path，不含 query
```

## 6. `bd-ticket-guard`（写接口的核心）

### 6.1 需要的素材

| 素材 | 来源 | 说明 |
|---|---|---|
| `private_key` | 浏览器生成 | P-256，**本机私有** |
| `ticket` | 登录时下发 | `hash.xxx` |
| `ts_sign` | 登录时下发 | `ts.<ver>.xxx` |
| `client_cert` | 登录时下发 | `pub.xxx` |

### 6.2 5 个请求头

| 头 | 值 |
|---|---|
| `bd-ticket-guard-ree-public-key` | 私钥推导的公钥（b64） |
| `bd-ticket-guard-version` | `2` |
| `bd-ticket-guard-web-version` | 从 `ts_sign` 解析 |
| `bd-ticket-guard-web-sign-type` | `1`=hmac / `0`=ecdsa |
| `bd-ticket-guard-client-data` | **仅写接口带**，只读接口不带 |

### 6.3 client-data 的签名内容

```python
res_sign = f"ticket={ticket}&path={api}&timestamp={timestamp}"
# hmac 模式（有 ecdh_key）：HMAC-SHA256(ecdh_key, res_sign)
# ecdsa 模式（兜底）：ECDSA(prv, res_sign)
```

`ecdh_key` 来源：`ECDH(客户端私钥, 服务端证书公钥) → HKDF-SHA256 → 32 字节`

### 6.4 两种封装

```python
headers.with_bd_readonly(auth)              # 只读：4 个头，无 client-data
headers.with_bd(api_path, auth)             # 写：5 个头，含 client-data
```

> ⚠️ **只读接口浏览器确实不发 client-data**，多了反而是「与浏览器不一致」。

### 6.5 一致性校验（必做）

```python
a.ticket_matches_session()
# 比对 ts_sign 前缀 vs cookie 里的 bd_ticket_guard_ts_sign_id
# 不一致说明 ticket 和 cookie 来自不同次登录
```

**还要额外校验 `client_cert` 与私钥推导公钥是否一致**（`ticket_matches_session` 不查这个）。

## 7. `x-secsdk-csrf-token`

```python
from utils.dy_util import generate_csrf_token
token = generate_csrf_token(cookies_str, origin='https://www.douyin.com')
```

**必须按子域取**：csrf token 与 `csrf_session_id` 绑定。

| 域 | origin |
|---|---|
| `www.douyin.com` | `https://www.douyin.com` |
| `creator.douyin.com` | `https://creator.douyin.com` |

换 token 的探针端点是 `anchor/search`，取响应头 `X-Ware-Csrf-Token` 的第 1 段。

## 8. 外部文章核对结论

对照文章《抖音创作者发文风控参数分析》逐条核验：

| 维度 | 文章 | 本项目 |
|---|---|---|
| csrf 端点 | `anchor/search`，取第 1 段 | ✅ 一致，且取 1+4 段、处理子域绑定 |
| dtrait 外层 | `d0_xx_xx`，RSA + AES-CBC | ✅ 一致，且明确 PKCS#1 v1.5 / PKCS7 / IV 前置 |
| dtrait 内层 | `prepend` 硬编码 | ✅ **超过文章**：解出头字节位域 + bool 位图 + tag 映射 |
| client-data | 只说「要算 req_sign」 | ✅ **超过文章**：解出被签内容、算法、双模式切换 |

**结论：项目实现完整度超过文章。**
