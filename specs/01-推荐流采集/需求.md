## 一句话目标

定时（例如每小时一次）抓取抖音**推荐流**，从中筛选出**特定主题**（如 AI 技术、艺术、读书）的视频，把**视频文件**和**抖音评论**下载到本地保存。

---

## 背景与范围

- 项目当前读接口（作品详情 / 评论 / 搜索 / 用户主页 / 直播）已验证可用；写接口不可用，与本需求无关，本需求**只做读**。
- 推荐流的 API 封装已完成：`DouyinAPI.get_tab_feed()` 走 `/aweme/v1/web/tab/feed/`（原 `get_feed()` 用的 `module/feed` 端点已废弃，方法已删除，见下文"技术现状"），因此本需求可以直接基于该方法开发采集流程。
- 本需求不含：点赞/评论/发布等写操作、账号登录、数据可视化前端。

---

## 功能拆解

### 1. 定时调度

按固定周期（默认设想：每 1 小时）自动跑一次完整采集流程。

- **已知可行性**：完全可行，与抖音接口无关，属于本机工程问题。可选实现：Windows 任务计划程序（`schtasks`）拉起一次性脚本，或常驻进程 + 调度库（如 APScheduler）。
- **主要风险**：无接口风险；风险在"每轮跑多久"与"下一轮是否重叠"——单轮耗时若超过周期，需要跳过或排队（见待确认问题 Q3）。

### 2. 推荐流抓取

调用 `/aweme/v1/web/tab/feed/`（GET）拉取推荐流，按 `refresh_index` 递增翻页，用 `aweme_id` 去重，得到一批候选作品。

- **已知可行性**：✅ 实测可用。`status_code=0`，单次响应 300+ KB，每条作品 89 个字段。需要 `a_bogus` 签名 + `msToken` + cookie；**不需要** secsdk webSign，**不需要** bd-ticket-guard。
- **关键约束**：`count` 参数不可靠（请求 10 / 20 都只返回 2~6 条），只能靠 `refresh_index` 递增多轮刷新累积；**必须用 `aweme_id` 去重**。

### 3. 主题筛选

从候选作品里挑出属于指定主题的（AI 技术 / 艺术 / 读书 等），只对筛中的作品继续下载。

- **已知可行性**：✅ **方案已验证**，采用大模型（LongCat-2.5-Preview）语义判定。实测 8 条真实样本：明显正确 6/8、边缘可争议 2/8、明显错误 0/8，优于关键词匹配（关键词会误命中作者名含"AI"的历史视频、漏召无"艺术"字样的钢琴曲）。详见 [技术方案-主题筛选.md](技术方案-主题筛选.md)。
- **主要风险**：依赖外部 API，服务不可用时本轮不下载任何内容（兜底策略见技术方案 §6）；置信度阈值需按实际效果微调（默认 0.8）。

### 4. 视频下载

对筛中的作品下载视频文件到本地。

- **已知可行性**：✅ 可行。作品数据里 `video.play_addr.url_list` 含直链；项目已有 `utils/data_util.py` 的 `download_work()` 可直接复用。
- **主要风险**：直链有时效性，必须"抓到就下"而不是攒着批量下；单条视频体积 × 每小时条数决定磁盘占用（见待确认问题 Q3）。

### 5. 评论抓取

对筛中的作品抓取抖音评论并落盘。

- **已知可行性**：✅ 已有实现。`dy_apis/douyin_api.py` 中 `get_work_all_comment(auth, url)` / `get_work_all_out_comment` / `get_work_all_inner_comment`，走 `/aweme/v1/web/comment/list/`，实测可用。
- **主要风险**：评论量可能很大，需要条数上限；一级评论与二级回复是否都要抓（见待确认问题 Q4）。

### 6. 本地存储

把视频文件、评论、作品元数据按可检索的方式存到本地。

- **已知可行性**：✅ 可行，属于本机工程问题。最小形态是"每作品一个目录：`作品.mp4` + `评论.json` + `元数据.json`"；是否需要数据库索引（SQLite / CSV）待定。
- **主要风险**：跨轮去重需要一张持久化的"已采 `aweme_id` 表"，否则每小时会重复下载同一条（见待确认问题 Q5）。

## 技术现状（实测事实，供实现参考）

以下为**已实测确认**的结论，实现时直接采用，不要重新试探。

### 推荐流接口

- 正确端点：`/aweme/v1/web/tab/feed/`（**GET**）。
- 原项目的 `get_feed()` 走的是 `/aweme/v1/web/module/feed/`，**实测已废弃**：返回 HTTP 200 但 body 为空。该方法已被删除。
- 现封装为 `DouyinAPI.get_tab_feed(auth, count='10', refresh_index='1')`（`dy_apis/douyin_api.py`），返回 `aweme_list` / `has_more` / `log_pb` / `status_code`，**不做去重**，调用方须按 `aweme_id` 自行去重。
- `tab/feed` 实测 `status_code=0`，单次返回 300+ KB，每条作品 **89 个字段**。
- 翻页靠 `refresh_index` **递增**（从 1 开始）。`count` 参数不可靠——请求 `count`=10 或 20 都只返回 2~6 条。
- 实测 8 轮刷新共得 **41 条唯一作品，零重复**。
- 无间隔连发 10 次**全部成功**，未触发限频。
- 签名要求：需要 `a_bogus` + `msToken` + cookie；**不需要** secsdk webSign，**不需要** bd-ticket-guard。
- **必须用 `aweme_id` 去重**。

### 评论接口

- 已有实现可直接调用：`DouyinAPI.get_work_all_comment(auth, url)` / `get_work_all_out_comment` / `get_work_all_inner_comment`。
- 端点 `/aweme/v1/web/comment/list/`，实测可用。

### 视频下载

- 作品数据的 `video.play_addr.url_list` 含视频直链。
- 项目已有 `utils/data_util.py` 的 `download_work()` 可下载视频。

### 已知坑

- **循环导入**：任何脚本必须**先** `import dy_apis.douyin_api`，**再** import 其他模块。
- **终端编码**：运行时需设 `PYTHONIOENCODING=utf-8`，否则中文输出会崩。
- **依赖安装**：`protobuf` 存在硬冲突，不能用 `pip install -r requirements.txt` 一把装，需按 `docs/主题/T01-环境搭建.md` 的三步装法。

## 验收标准建议

需求上线（可交付）时，建议按以下标准验收：

1. **调度可自动**：不人工干预，连续 3 个整点各自动跑完一轮，日志里有每轮的开始/结束时间与结果计数。
2. **抓取量达标**：单轮从 `tab/feed` 获得 **≥ 30 条唯一作品**（依据实测 8 轮刷新 41 条唯一作品，10 轮应不低于此量级）；同一轮内 `aweme_id` 零重复。
3. **筛选可解释**：每条被筛中的作品能指出命中了哪个主题、置信度是多少；低于阈值被筛掉的作品也留有元数据记录，便于事后调阈值回溯采纳。
4. **视频完整落盘**：筛中的作品有可正常播放的 `.mp4`，文件大小 > 0 且与响应中直链一致；下载失败的作品有明确失败原因记录，不静默丢弃。
5. **评论落盘**：每条筛中作品有对应评论文件，条数 = 接口实际返回条数（受上限约束），结构与源码解析结果一致。
6. **跨轮不重复下载**：连续跑 3 轮，已采 `aweme_id` 不会重复下载视频；去重表可查询、可人工清理。
7. **不破坏现有能力**：全程只调读接口，不触发写接口（不点赞/不评论/不发布）；不修改 `.env` 与浏览器 profile。
8. **失败可见**：限频、直链失效、空响应等异常在日志中可定位到具体作品与具体原因。
