## Q2 · `wmic` 依赖失效

**状态**：🟡 已知未修

### 现象

`browser_credential.py:78` 的 `running_chrome_user_data_dirs()` 调用 `wmic`：

```python
out = subprocess.run(["wmic", "process", "where", ...])
```

**Windows 11 build 26300 已移除 wmic**，异常被 `except Exception: return []` 静默吞掉。

### 影响

- 便携版 Chrome 的 `--user-data-dir` 探测失效
- Edge / 360 走硬编码 `BROWSERS` 列表，**不受影响**

### 修复方案

改用 `Get-CimInstance Win32_Process`：

```powershell
Get-CimInstance Win32_Process -Filter "Name='chrome.exe'" | Select-Object CommandLine
```

## Q4 · Edge Cookies 库被清空（事故）

**状态**：⚫ 已发生，不可逆

### 事实

| 时间 | 状态 |
|---|---|
| 09:55 | 66 条抖音 cookie |
| **10:04:34** | **0 行**（`freelist_count: 21` / `page_count: 26`，整表删除） |
| 现在 | 0 行 |

**影响范围：所有站点，不只是抖音。**

### 原因

CDP 实验中对**真实** Edge profile 反复用 `--user-data-dir` 启动无头/带窗口/目录联接实例，并多次 `Stop-Process -Force`。Edge 在非正常启动路径下重建了 cookie 存储。

### 处理

**需要用户在 Edge 中重新登录各站点。**

### 教训

> **永远不要对真实浏览器 profile 做实验性启动。**
>
> 正确做法：
> 1. 复制 profile 到临时目录（但 App-Bound 会导致解密失败 → 此时应直接判定不可用）
> 2. 或换一个不启用 App-Bound 的浏览器
> 3. 需要退出浏览器时让用户自己退，不要 `Stop-Process`

## Q5 · `client_cert` 与私钥配对缺少显式校验

**状态**：🟢 低优先级

### 现象

`auth.ticket_matches_session()` 只比对 `ts_sign` 与 cookie 的 `bd_ticket_guard_ts_sign_id`，**不检查 `client_cert` 是否等于私钥推导的公钥**。

### 影响

若 leveldb 里残留多份历史记录（各自绑不同私钥），可能注入错的那份，导致写接口失败且报错信息看不出根因。

### 现状

`browser_credential.py` 已按「`client_cert` 匹配度打分 + `create_time` 兜底」选择，但 `builder/auth.py` 侧没有对应校验。

### 建议

在 `auth` 里加一个 `cert_matches_key()`，与 `ticket_matches_session()` 并列使用。
