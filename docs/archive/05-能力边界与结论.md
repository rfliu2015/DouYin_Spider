### 最值得借鉴的三点

**1. 纯 Python secsdk（`utils/secsdk_web_sign.py`，187 行）**

dyclaw 的 `web_sign.py` 里有一段注释暴露了痛点：

> `secsdk 会做无头环境检测，headless 下大概率不加载，因此这里给足时间并提示原因`
> `headless 模式下 secsdk 通常不加载，请用 headless=False`

Douyin_Spider 把 secsdk 算法用 Python 重写了，**既不需要浏览器，也不用担心无头检测**。实测可直接调用：

```python
from utils.secsdk_web_sign import sign_url, PROTECTED_PATHS_GET
# PROTECTED_PATHS_GET: 14 条路径
sign_url('https://www.douyin.com/aweme/v1/web/aweme/detail/?aweme_id=...',
         ts=..., uifid=...)
```

搬过去就能让 dyclaw 的 `WebSigner` 彻底去掉浏览器依赖。

**2. 按 host 区分的 a_bogus profile**

```python
# utils/ab_pure.py:41
HOST_APP_IDS = {
    "www.douyin.com":     (6383, 11881),
    "live.douyin.com":    (6383, 7571),
    "creator.douyin.com": (2906, 33638),
    "login.douyin.com":   (6383, 6241),
}
```

签名里内嵌 `(aid, page_id)`，**www / live / creator 三套值不同，用错会判人机验证**。dyclaw 只有 www 的 profile，一旦要碰 creator 就会踩。

**3. 纯 HTTP 扫码登录（`dy_apis/login_api.py`）**

流程：`bootstrap_auth` → `qrcode_login`（60 秒过期自动换码）→ `check_qrconnect` 轮询 → `_follow_login_redirect` 收 cookie → `save_credential` 写 `.env`。

**但本次实测失败**（fpk1 问题），所以这条路线的可行性在 dyclaw 的浏览器方案面前并不占优。

## 3. 核心结论

### 关于「这个项目比 dyclaw 有什么改进」

**在 cookie 路径下，读能力基本等价，没有实质改进。**

真正的差距（写接口、创作者中心、ticket 机制）**全部依赖扫码登录**，而扫码登录被 fpk1 卡住。

### 关于「登录自动化」

你的直觉是对的：**cookie 是登录的产物，提供 cookie 就不需要登录自动化**。但要补充一个关键点：

> **cookie 只够「读」，不够「写」。** 写接口需要的 `ticket` / `ts_sign` / `private_key` 中，**私钥是本地生成的**，不会跟 cookie 一起复制。

所以两个场景是分开的：

- 只想读（评论、作品、用户）→ 贴 cookie 就够，**不需要登录自动化**
- 要写（发评论、点赞、收藏、发布）→ 必须走一次登录，因为要生成自己的密钥对

### 关于「扫码登录是否必要」

README 明确：

> `- 🔑 **多种登录方式**`
> `  - Cookie / 扫码登录 / 手机号验证码登录`

并且首推 cookie。**扫码是补充手段，不是主路径。**

## 5. 后续建议

### 如果目标是「用这个项目采集数据」

**现状已够用。** cookie 路径能跑通作品详情、评论、回复、作品列表、搜索、直播。建议：

1. 保留 `.env`
2. 用 `main.py` 的 1/2/3 段（作品 / 用户全部作品 / 搜索），注意第 4 段会真的发私信
3. 跳过用户主页接口，或改用作品详情里自带的 author 字段

### 如果目标是「研究它的实现」

**最有价值的部分是纯 Python 签名栈**：

| 模块 | 行数 | 价值 |
|---|---|---|
| `utils/secsdk_web_sign.py` | 187 | 纯 Python webSign，可移植到 dyclaw |
| `utils/ab_pure.py` | ~400 | 按 host 区分的 a_bogus |
| `utils/dtrait_features.py` | 225 | dtrait 内层 VM 纯 Python 实现 |
| `utils/bd_ticket.py` | ~300 | ECDH + HKDF + HMAC/ECDSA 双模式 |
| `dy_live/protobuf/` | 9 个 proto | 完整直播协议定义 |

### 如果目标是「打通扫码登录」

**需要解决 fpk1 设备指纹**。可行路径：

1. 从本机 Chrome 抓取完整设备身份（fpk1 + fpk2 + UA + canvas/WebGL/字体样本）
2. 写成 `utils/challenge_profile.json` 格式，通过 `DY_FP_COMPONENTS_FILE` 指定
3. **注意**：仍需解决「新生成的 P-256 密钥 vs 旧指纹」的矛盾

**风险提示**：限频（`error_code=7`）是服务端冷却，反复重试会加重。实测间隔 3 天仍会触发。
