## 3. 实测：`key-sign-result: 2`

### 3.1 真实响应（重要修正）

> ⚠️ **历史文档 08 记录的「HTTP 403」是误判。**
> `check_risk_response` 把空 body 当成了风控。

**实测真实响应是 HTTP 200**：

```
HTTP 200
bd-tt-error-code: 8
bd-ticket-guard-key-sign-result: 2                    ← 服务端明确告知 ticket 签名校验失败
bd-ticket-guard-sign-res-static-ts-sign: 1102
bd-ticket-guard-sign-res-static-sign: 1102
body: {"status_code":8,"status_msg":"用户未登录","log_pb":{...}}
```

### 3.2 已排除的变量

| 变量 | 结果 |
|---|---|
| `digg` 用 `with_bd_readonly()`（4 头，无 client-data） | `key-sign-result: 2` |
| `digg` 用 `with_bd()`（完整，**含 `bd-ticket-guard-client-data`**） | **完全相同** |
| `digg type=1`（点赞） | 同上 |
| `digg type=0`（取消） | 同上 |

**结论：不是缺 client-data，不是方向问题。**

## 4. 关键机制：写请求会作废会话 ticket

> 这是 2026-10-29 通过对照实验确定的。

### 4.1 第一轮：写请求后凭证失效

| 时间 | 事件 |
|---|---|
| 10:13:40 | `profile/self` **成功**（`status_code: 0`） |
| 10:14:09 | 第一次 `digg` 调用 |
| 10:14:38 | 手工 `digg` 诊断（`key-sign-result: 2`） |
| 10:16:08 起 | `profile/self` **稳定失败**，`status_code: 8` |

### 4.2 第二轮：不发写请求则凭证稳定

| 时间 | 动作 | 结果 |
|---|---|---|
| — | 全新凭证（`ticket hash.5xW9F7…`） | — |
| — | `profile/self` ×3（间隔 3s） | **3/3 通过** |
| — | `get_work_info` | OK |
| +20s | `profile/self` 再测 | **仍通过** |

### 4.3 结论

1. **凭证没有时效问题**
2. **是写请求作废了会话 ticket**
3. 作废后的表现（`status_code: 8`）与 `digg` 失败码**完全一致**

**推论**：`key-sign-result: 2` 不是「凭证坏了」，而是「这次写请求的签名没通过」。**作废是后果，不是原因。**

### 4.4 对实验方法的影响

> 🚨 **每次写接口失败都会作废当前 ticket。**
> 用已作废的凭证做任何写接口实验，都会得到假阴性。
> **每轮实验前必须重新登录取新凭证。**

## 6. 根因的两种可能

| 可能 | 说明 | 可修性 |
|---|---|---|
| **A. 签名算法不匹配** | 凭证注入旁路生成的 `req_sign` 与浏览器真实行为有偏差 | ✅ 可修 |
| **B. 服务端环境校验** | 要求请求来自真实浏览器环境（dtrait / fpk1 等） | ❌ 可能走不通 |

**目前无法区分。**

### 若为 A，重点检查

```python
# utils/bd_ticket.py
res_sign = f"ticket={ticket}&path={api}&timestamp={timestamp}"
```

需对照浏览器实录确认三点：
1. `timestamp` 单位（秒 / 毫秒）
2. `path` 是否含 query
3. `ticket` 是否需 URL 编码

## 7. 当前建议

| 场景 | 建议 |
|---|---|
| 只是想采集数据 | **放弃写接口**，读能力已足够 |
| 想研究逆向 | 可继续攻 `bd_ticket_guard`，但**每轮实验需重登** |
| 生产使用 | **不要依赖写接口**——不仅不通，还会作废会话导致读能力中断 |

> ⚠️ 写接口失败会连带影响读能力（ticket 作废后 `profile/self` 也挂）。**在拿到稳定方案前，不要在生产环境碰写接口。**
