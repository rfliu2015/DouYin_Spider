## 1. 为什么不用关键词匹配

最初设想用关键词表匹配主题，**实测证明不可行**。

### 1.1 真实样本踩坑证据

用 31 条真实推荐流样本验证，关键词匹配有三类结构性缺陷：

| 缺陷 | 样本 | 说明 |
|---|---|---|
| **误命中** | `[AI商业人生] 拿破仑百日王朝` | 作者名含 "AI"，内容是历史故事 |
| **漏召** | `[Vinheteiro] 20首钢琴曲 #钢琴 #古典音乐` | 没有"艺术"字样，但确属艺术 |
| **漏召** | `[内语者] 荣格的个性化地图 #心理学` | 语义相关但没有"读书"字样 |

**更致命的是**：31 条样本中有 **3 条 desc 为空**（作者信息也取不到），关键词匹配对这类完全失效。

### 1.2 字段可用性实测

| 字段 | 覆盖率 | 说明 |
|---|---|---|
| `desc` | **93%** | 中位 51 字，最长 508 字 |
| `text_extra`（话题标签） | **84%** | 平均 2~5 个 |
| `caption` | 90% | 与 desc 高度重叠 |
| `music.title` | 93% | 音乐类强信号 |
| `anchor_info` | 9% | 很少有人挂 |
| `seo_info` | **0%** | 字段存在但全空，不可用 |

**结论**：text 信号足够丰富，支持语义判定；但关键词表无法表达边界。

## 2. 方案：三层漏斗

```
推荐流（约 40 条/轮，来自 get_tab_feed）
    │
    ├─【第 1 层】规则预过滤 ── 零成本、零延迟
    │   • desc 为空且无话题标签 → 直接丢弃（实测约 10%）
    │   • 命中强负向词（游戏/带货/擦边）→ 丢弃
    │
    ├─【第 2 层】大模型批量判定 ── 一次请求判完一批
    │   • 输入：40 条精简信息（desc 截 120 字 + 话题 ≤6 个）
    │   • 输出：命中条目 + 主题 + 置信度
    │
    └─【第 3 层】置信度分流
        • conf ≥ 0.8  → 采信，下载视频 + 抓评论
        • conf < 0.8  → 不下载，仅记录元数据（可回溯调阈值）
```

### 2.1 设计理由

| 设计点 | 理由 |
|---|---|
| **批量而非逐条** | 40 条一次请求，省去 40 次网络往返与 system prompt 重复开销 |
| **规则前置** | 明显无关的内容不必花钱让模型判 |
| **desc 截 120 字** | 实测中位 51 字，120 足够；不传全文可省约 3 倍 token |
| **返回编号而非全文** | 输出只要 `{"i":8,"topics":[...]}`，避免模型复述原文 |
| **置信度而非布尔** | 边界样本（荣格心理学算不算读书）需要阈值可调 |

## 3. 模型选型与实测

### 3.1 配置

| 项 | 值 |
|---|---|
| 服务商 | LongCat |
| Base URL | `https://api.longcat.chat/openai/v1` |
| 模型 ID | **`LongCat-2.5-Preview`** |
| 协议 | OpenAI 兼容（`/chat/completions`、`/models`） |
| 备用模型 | `LongCat-2.0` |

**凭证存放**：`E:\Code\Projects\DouYin_Spider\.env`

```bash
LONGCAT_BASE_URL='https://api.longcat.chat/openai/v1'
LONGCAT_MODEL='LongCat-2.5-Preview'
LONGCAT_API_KEY='ak_...'
```

> `.env` 已在 `.gitignore` 第 40 行，不会入库。

### 3.2 ⚠️ 这是推理模型

响应结构除标准字段外，`message` 里**多一个 `reasoning_content`**：

```json
{
  "choices": [{
    "message": {
      "role": "assistant",
      "content": "{\"hits\":[...]}",
      "reasoning_content": "\n用户要求...让我确认一下..."
    }
  }],
  "usage": {
    "completion_tokens": 74,
    "completion_tokens_details": { "reasoning_tokens": 70 }
  }
}
```

**影响**：
- 即使简单任务也会产生推理 token（测试"回复两个字"用了 70 个）
- **completion_tokens 是大头**，成本比普通模型高
- 解析时只读 `content`，**忽略 `reasoning_content`**

### 3.3 判定质量实测（8 条真实样本）

| # | 内容 | 判定 | 评价 |
|---|---|---|---|
| 1 | 剑网3 游戏公测 | 不命中 | ✅ 正确排除 |
| 2 | DeepSeek Harness 插件 | AI技术 0.95 | ✅ 正确 |
| 3 | 《源泉》安兰德书评 | 读书 0.95 | ✅ 正确 |
| 4 | 钢琴 20 首曲子 | 艺术 0.95 | ✅ **关键词必漏，模型命中** |
| 5 | DeepSeek 开机动画 | AI技术 0.72 | ⚠️ 边缘（品牌相关，内容是动画） |
| 6 | 读懂毛选后社恐消失 | 读书 0.76 | ⚠️ 边缘（是书，主线是心理自助） |
| 7 | 荣格个性化地图 | 读书 0.85 | ✅ **关键词必漏，模型命中** |
| 8 | 悬疑惊悚片 | 不命中 | ✅ 正确排除（影视非读书） |

**明显正确 6/8，边缘可争议 2/8，明显错误 0/8。**

### 3.4 成本实测

| 项 | 实测值 |
|---|---|
| 8 条样本耗时 | **5.3 秒** |
| 8 条 prompt_tokens | 561 |
| 8 条 completion_tokens | **968**（推理占大头） |
| 40 条/轮推算 | ≈ **7,945 tokens** |
| 每天 24 轮 | ≈ 19 万 tokens |
| **每月（30 天）** | **≈ 570 万 tokens** |

> 按 LongCat 定价估算为**每月几元到十几元**，可接受。

**优化空间**：prompt 里要求"直接输出 JSON 不要推理"能略降，但推理是模型特性，收效有限。

## 4. Prompt 设计

### 4.1 System Prompt 模板

关键：**每个主题必须写边界和反例**，不能只给主题名。

```
你是短视频主题分类器。判断每条视频是否属于下列主题。

【AI技术】人工智能、大模型、机器学习、AI工具/插件、算法、神经网络。
  反例：作者名含"AI"但内容无关的不算（如历史人物故事）；非AI的科技产品评测不算。

【艺术】绘画、音乐、古典乐、乐器演奏、舞蹈、雕塑、建筑美学、摄影。
  反例：音乐榜单八卦、明星绯闻不算。

【读书】书籍推荐、书评、名著解读、作者介绍、阅读方法、哲学、心理学。
  反例：影视剧解说原著不算（属影视）；纯历史事件叙述不算。

只输出JSON，不要任何解释：
{"hits":[{"i":序号,"topics":[{"name":"主题名","conf":0.0到1.0}]}]}
不命中的条目不出现。
```

> 反例条款是准确率的关键。实测中模型正是靠"作者名含AI不算"排除了样本 1，靠"哲学心理学算读书"命中了样本 7。

### 4.2 输入格式

```json
[
  {"i":1,"t":"desc 前 120 字","g":["话题1","话题2"]},
  {"i":2,"t":"...","g":["ai","dsh"]}
]
```

- `i` = 批内序号（用于回填结果）
- `t` = desc 截断 120 字
- `g` = 话题标签，最多 6 个

### 4.3 输出格式

```json
{
  "hits": [
    {"i": 2, "topics": [{"name": "AI技术", "conf": 0.95}]},
    {"i": 3, "topics": [{"name": "读书", "conf": 0.95}]}
  ]
}
```

**多标签**：一条视频可以命中多个主题，`topics` 是数组。

### 4.4 调用参数

```python
payload = {
    'model': 'LongCat-2.5-Preview',
    'messages': [
        {'role': 'system', 'content': SYSTEM_PROMPT},
        {'role': 'user', 'content': json.dumps(samples, ensure_ascii=False)},
    ],
    'temperature': 0,      # 必须 0，保证可复现
    'max_tokens': 2000,
}
```

## 5. 阈值策略

### 5.1 建议 0.8

依据实测分布：

| 置信度区间 | 样本 | 特征 |
|---|---|---|
| **≥ 0.9** | 2, 3, 4 | 主题明确，无争议 |
| **0.8 ~ 0.9** | 7 | 语义相关但需推理 |
| **0.7 ~ 0.8** | 5, 6 | 边缘，主线不是该主题 |
| < 0.7 | — | 实测未出现 |

**取 0.8**：采信 2/3/4/7（都是高质量），过滤 5/6（边缘）。

### 5.2 可调性

阈值存配置（`.env` 或 JSON），**不硬编码**。低于阈值的不丢弃，只记元数据，之后可批量回溯采纳。

---

## 6. 兜底策略

| 情况 | 处理 |
|---|---|
| desc 为空且无标签 | 直接丢弃，不送模型（省成本） |
| 模型返回非法 JSON | 重试 1 次；再失败则本轮跳过该批，记日志 |
| 模型超时 / 5xx | 跳过本轮，**不下载任何视频**（宁可少采不乱采） |
| 模型说都不命中 | 正常结果，不是错误 |
| API Key 缺失 | 启动时直接报错退出，不静默降级为关键词匹配 |

> **原则**：筛选层失败时，本轮不产生任何下载，避免污染数据集。

## 7. 实现落位建议

| 模块 | 位置 | 职责 |
|---|---|---|
| 判定器 | `utils/topic_classifier.py` | 封装 LongCat 调用、prompt、JSON 解析、重试 |
| 配置 | `.env` | base_url / model / api_key / 阈值 |
| 主题定义 | `specs/01-推荐流采集/主题定义.json`（或内嵌） | 主题名 + 描述 + 反例，便于用户增删 |

**接口建议**：

```python
class TopicClassifier:
    def __init__(self, base_url, model, api_key, themes, threshold=0.8): ...
    def classify(self, items: list[dict]) -> list[dict]:
        """items: [{i, t, g}] -> [{i, topics:[{name, conf}]}]"""
```

**与现有代码零耦合**：只依赖 `get_tab_feed()` 的返回值，不改任何现有模块。
