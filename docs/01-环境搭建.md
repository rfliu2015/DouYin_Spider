## 2. 依赖安装：requirements.txt 直接装会失败

### 问题

```
$ pip install -r requirements.txt
ERROR: Cannot install -r requirements.txt (line 27) and protobuf>=5.27
       because these package versions have conflicting dependencies.

The conflict is caused by:
    The user requested protobuf>=5.27
    blackboxprotobuf 1.0.1 depends on protobuf==3.10.0
```

这是**硬冲突**，无法通过放宽版本解决。

### 冲突双方的需求

| 包 | 要求 | 原因 |
|---|---|---|
| `protobuf>=5.27` | 项目显式钉住 | `static/Response_pb2.py` 是 protoc 5.27.1 生成的，需要 `from google.protobuf import runtime_version` |
| `blackboxprotobuf==3.10.0` 依赖 | 上游元数据写死 | 见下方验证 |

### 关键验证：blackboxprotobuf 的元数据是错的

解包 sdist 后检查它实际 import 了什么：

```
blackboxprotobuf/lib/types/length_delim.py:5: from google.protobuf.internal import wire_format, encoder, decoder
blackboxprotobuf/lib/types/type_maps.py:4:    from google.protobuf.internal import wire_format
blackboxprotobuf/lib/types/varint.py:2:      from google.protobuf.internal import wire_format, encoder, decoder
```

它**只用了几个内部编码原语**，不依赖任何 3.10 特有行为。

实测两种 protobuf 版本下都能正确解码：

```python
import blackboxprotobuf
blackboxprotobuf.decode_message(bytes.fromhex('0a036162631001'))
# protobuf 5.29.6 → {'1': b'abc', '2': 1}
# protobuf 7.36.2 → {'1': b'abc', '2': 1}
```

**结论：`protobuf==3.10.0` 是过时的元数据声明，可安全忽略。**

### 反向验证：protobuf 4.x 根本跑不起来

```
$ PYTHONPATH=/tmp/pb4 pytest tests/
ImportError: cannot import name 'runtime_version' from 'google.protobuf'
```

所以**不能**为了迁就 blackboxprotobuf 而降级 protobuf。

## 3. 实际安装步骤

```bash
# 第 1 步：装除 protobuf / blackboxprotobuf 外的全部依赖
grep -v -E '^(protobuf|blackboxprotobuf)' requirements.txt | grep -v '^#' | grep -v '^$' > /tmp/req_rest.txt
pip install -r /tmp/req_rest.txt

# 第 2 步：装 protobuf 5.x（限定 <6 避免跨大版本）
pip install 'protobuf>=5.27,<6'        # → 5.29.6

# 第 3 步：跳过元数据约束装 blackboxprotobuf
pip install --no-deps blackboxprotobuf  # → 1.0.1
```

## 5. 环境层面的两个坑

### 坑 1：循环导入

```python
import builder.auth
# ImportError: cannot import name 'DouyinAuth' from partially initialized module
```

原因：
```
builder/auth.py:9        → from dy_apis import douyin_api
dy_apis/douyin_api.py:22 → from builder.auth import DouyinAuth
```

**规避方式**：必须先 `import dy_apis.douyin_api`，或直接 `import main`。任何独立脚本都要注意导入顺序。

### 坑 2：Windows GBK 终端导致二维码渲染失败

```
WARNING | print_qrcode | 终端二维码渲染失败: 'gbk' codec can't encode character '\u2580'
```

**解决**：设置 `PYTHONIOENCODING=utf-8`。
